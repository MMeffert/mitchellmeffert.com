## Tech Debt

### Tech Debt 1: Hero Image Not WebP (Acceptable)

**Phase:** 16 (Image Optimization)
**Description:** LCP element `code-background.png` (456KB) not converted to WebP.
**Impact:** 114-156KB potential savings (25-34% reduction).

**Rationale:** Intentional. Image used in:
- Open Graph meta tags (lines 87, 97, 110)
- CSS backgrounds (home-bg, bg-funfact, bg-client)

Converting would:
- Break social media preview caching (URL change)
- Require CSS refactor or multiple file versions

**Status:** Acceptable for v1.2. If production LCP >2.5s, revisit with `<picture>` wrapper around visible `<img>` instead of CSS background.

### Tech Debt 2: No Responsive srcset (Out of Scope)

**Phase:** 16 (Image Optimization)
**Description:** Images use single resolution. Mobile downloads desktop-size assets.
**Impact:** Unnecessary bytes on mobile (e.g., 750x500px blog images for 375px viewports).

**Status:** Out of scope for v1.2. WebP already provides significant savings. Defer responsive images to v1.3+ if mobile performance becomes concern.

### Tech Debt 3: No font-display Optimization (Low Risk)

**Phase:** 15 (Core Web Vitals)
**Description:** No `font-display` CSS property in stylesheets.
**Impact:** Potential CLS if web fonts load late and cause layout shifts.

**Mitigation:** Site uses Bootstrap default fonts (likely system fonts or well-cached CDN).

**Status:** Low priority. Monitor CLS metric in production. If CLS >0.1, add `font-display: optional` or `swap`.
